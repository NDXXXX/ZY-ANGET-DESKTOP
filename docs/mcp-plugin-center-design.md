# 插件与技能中心设计文档

状态：Draft  
更新时间：2026-09-19  
适用范围：`apps/desktop` 与 `packages/coding-agent/examples/extensions/mcp`

## 1. 背景

当前桌面端直接向用户展示 MCP 服务器概念、启动命令和 JSON 配置。该方式适合熟悉 MCP 的开发者，但普通用户必须理解 `stdio`、HTTP、命令参数和配置文件，才能安装一个工具。

具体例子：用户只是想让 Agent 操作浏览器，却需要先找到 Playwright MCP 包名，再填写：

```text
npx -y @playwright/mcp@latest
```

用户的真实目标是“安装浏览器插件”，不是“配置一个 stdio MCP 进程”。

本设计将 MCP 作为插件的底层实现隐藏起来。普通用户通过插件目录完成搜索、安装和移除；需要接入私有或未收录 MCP 的开发者，仍可通过“添加自定义”使用 URL、命令或 JSON。

## 2. 目标

### 2.1 产品目标

- 用户不需要理解 MCP 协议即可安装常用能力。
- 常用插件可通过一次点击完成安装。
- 已安装插件、可安装插件和自定义入口层级清晰。
- 保留对标准 MCP 配置的兼容性。
- 对本地命令、文件访问和远程授权给出明确的权限提示。
- 插件变更在新对话中稳定生效，并向用户明确说明生效时机。
- 插件与技能在同一个主页面中切换，不使用弹窗。
- 技能列表只展示当前 Agent 实际会加载的位置，区分个人与项目范围。

### 2.2 非目标

第一阶段不包含：

- 公共在线插件市场。
- 第三方开发者提交与审核系统。
- Gmail、GitHub 等服务的 OAuth 托管。
- MCP Apps 内嵌交互界面。
- 插件评分、评论、付费或推荐算法。
- 自动更新第三方 MCP npm 包。

## 3. 核心设计原则

### 3.1 面向能力，不面向协议

界面使用“浏览器自动化”“文件访问”“最新文档”等用户语言。`stdio`、进程命令和 JSON 只出现在自定义入口和诊断信息中。

### 3.2 渐进披露

默认页面只展示搜索、已安装和推荐插件。高级配置必须由用户主动打开。

### 3.3 安装简单，权限明确

低风险的内置插件可以一键安装。会执行本地程序、访问目录或连接账号的插件，在首次启用前展示权限说明。

### 3.4 状态必须真实

“已安装”只表示配置已经保存；“可用”表示 MCP 已成功连接并完成工具发现。界面不能用“已安装”掩盖连接失败。

### 3.5 保持兼容

继续读写 `~/.pi/agent/mcp-servers.json`，并接受生态常见的 `mcpServers` 配置结构。

## 4. 用户模型

### 普通用户

知道自己需要的能力，不知道 MCP 是什么。主要使用推荐插件和搜索。

### 高级用户

从项目 README 得到 MCP URL 或启动命令，希望快速粘贴接入。

### 开发者

需要诊断连接、查看服务器类型、工具列表和错误信息。

## 5. 信息架构

插件中心是与聊天区平级的主页面。点击左侧“插件”后，右侧工作区直接切换为插件页面；侧边栏、窗口控制和主导航保持不变。页面不使用遮罩、浮层、关闭按钮或居中的对话框容器。

### 5.1 页面头部

- 标题：插件。
- 副标题：说明插件为 Agent 增加哪些能力。
- 顶部“插件 / 技能”用于切换两个可用的扩展页面，当前类型使用选中态。
- 插件页右上角“添加”：展开自定义 MCP 高级配置区域。
- 技能页右上角“添加”：创建并打开个人技能目录，由用户放入 `SKILL.md`。

### 5.2 搜索

- 匹配插件名称、内部标识、分类和描述。
- 输入后实时过滤推荐插件。
- 没有结果时展示明确空状态。
- 第一阶段只搜索本地内置目录，不发起网络请求。

### 5.3 已安装

每个已安装插件展示：

- 图标和展示名称。
- 一句话能力说明。
- 运行状态：未连接、连接中、可用或错误。
- 移除操作。

自定义 MCP 没有目录元数据时，使用服务器名称首字母作为图标，并标记为“自定义”。

### 5.4 推荐插件

第一阶段内置以下插件：

| 插件 | 分类 | 安装参数 |
|---|---|---|
| Playwright | 开发工具 | 无 |
| Chrome DevTools | 开发工具 | 无 |
| Context7 | 知识与文档 | 无 |
| 文件系统 | 文件与数据 | 授权目录 |
| Memory | 效率 | 无 |
| Sequential Thinking | 效率 | 无 |

每个插件卡片包含图标、名称、分类、说明和安装按钮。已经安装的插件显示勾选状态，不能重复安装。

### 5.5 添加自定义

自定义入口接受三种输入：

```text
https://example.com/mcp
```

```text
npx -y @example/mcp
```

```json
{
  "mcpServers": {
    "example": {
      "command": "npx",
      "args": ["-y", "@example/mcp"]
    }
  }
}
```

系统负责推断传输类型和服务器名称。解析失败时保留原始输入并在当前区域展示错误，不关闭面板。

### 5.6 技能页面

技能页面与插件页共用主页面框架，不打开弹窗或子窗口。

```text
┌──────────────┬──────────────────────────────────────────────────────────┐
│ 插件  ← 当前 │  插件  [技能]                                [＋ 添加] │
│              ├──────────────────────────────────────────────────────────┤
│              │ 技能                                                     │
│              │ 通过任务专用技能扩展 Agent 的能力                       │
│              │                                                          │
│              │ [ 搜索技能                                             ] │
│              │                                                          │
│              │ 已安装  6                                                │
│              │ [全部]  个人  项目                                       │
│              │                                                          │
│              │ 图标  Skill A          图标  Skill B                     │
│              │       描述 · 个人             描述 · 项目                │
└──────────────┴──────────────────────────────────────────────────────────┘
```

- 搜索匹配技能名称和描述。
- “全部 / 个人 / 项目”按来源过滤。
- 每个技能展示名称、描述、来源和文件路径提示。
- 没有技能时展示真实空状态，不填充模拟推荐数据。
- 个人技能来源：`~/.pi/agent/skills`、`~/.agents/skills`。
- 项目技能来源：当前项目 `.pi/skills`，以及从当前项目向上查找的 `.agents/skills`。
- 目录递归发现规则与 Coding Agent 一致：目录含 `SKILL.md` 时将其视为技能根目录，不继续向下扫描。

## 6. 核心交互

### 6.1 安装内置插件

```text
点击安装
  → 检查是否需要额外参数
  → 必要时确认权限
  → 写入 MCP 配置
  → 更新为“已安装”
  → 提示“将在下次对话中生效”
```

配置写入成功前不能提前显示“已安装”。写入失败时保持原状态并展示错误。

### 6.2 安装文件系统插件

文件系统插件要求用户提供目录。目标交互分两步：

1. 点击安装。
2. 通过系统目录选择器选择授权目录，并确认 Agent 将获得该目录的读写权限。

当前文本路径输入框是过渡方案。后续应改用系统目录选择器，避免路径输入错误。

### 6.3 移除插件

- 点击移除后立即更新配置。
- 移除只删除插件配置，不删除插件曾访问或生成的数据。
- 如果当前 Agent 会话正在使用该插件，当前会话保持不变；新对话不再加载。
- 删除远程插件时，是否撤销 OAuth 授权必须单独说明，不能默认等同于移除配置。

### 6.4 自定义 MCP

```text
打开“添加自定义”
  → 粘贴 URL、命令或 JSON
  → 本地解析和校验
  → 展示名称、传输方式和权限摘要
  → 用户确认
  → 保存配置
```

第一阶段已实现直接解析并保存。权限摘要和连接测试属于下一阶段。

### 6.5 生效时机

MCP 工具在 Agent 启动时注册，因此安装或移除后：

- 当前对话不热重载工具。
- 新建或重新连接对话后生效。
- 成功提示必须包含该说明。

## 7. 状态设计

插件安装状态和运行状态应分开建模。

| 状态 | 含义 | 用户操作 |
|---|---|---|
| `available` | 可以安装 | 安装 |
| `installing` | 正在写入配置 | 等待 |
| `installed` | 已写入配置，尚未连接 | 新建对话 |
| `connecting` | Agent 正在建立 MCP 连接 | 等待 |
| `ready` | 已发现工具，可以调用 | 查看能力 |
| `error` | 启动、认证或协议失败 | 查看错误、重试、移除 |
| `disabled` | 保留配置但不加载 | 启用 |

第一阶段仅实现 `available`、`installing` 和 `installed`。运行状态需要主进程与 Agent 上报连接结果。

## 8. 权限与安全

MCP 服务器可能启动任意本地进程、访问文件、发送网络请求或修改第三方数据。简化安装界面不能隐藏这些风险。

### 8.1 风险等级

| 等级 | 示例 | 安装要求 |
|---|---|---|
| 低 | 只读远程文档查询 | 展示权限摘要 |
| 中 | 浏览器控制、网络调试 | 首次启用前确认 |
| 高 | 本地文件读写、本地命令、自定义 MCP | 明确警告并确认范围 |
| 账号授权 | Gmail、GitHub、Slack | 展示 OAuth 权限并由用户完成授权 |

### 8.2 配置来源

- 只自动加载用户级配置。
- 不自动加载项目内 MCP 配置，避免仓库静默执行命令。
- 自定义 MCP 必须标记为未审核。
- 在线目录引入后，目录元数据必须包含来源、版本和权限声明。

### 8.3 凭据

- 不在插件目录清单中保存 token。
- 不在 UI 或日志中完整展示认证 header。
- OAuth token 应存入系统安全存储，不写入普通 JSON 文件。
- 环境变量中的 secret 只传给目标 MCP 子进程。

### 8.4 配置写入

目标实现应使用临时文件加原子替换，避免写入中断损坏配置。读取失败不能伪装为空配置，否则用户保存时可能覆盖原文件。

## 9. 数据模型

目录展示信息与 MCP 运行配置分离。

```ts
interface PluginManifest {
  id: string;
  displayName: string;
  description: string;
  category: string;
  icon: string;
  source: "builtin" | "remote" | "custom";
  permissions: PluginPermission[];
  setup?: PluginSetupField[];
  mcp: McpServerConfig;
}

type PluginPermission =
  | { type: "filesystem"; mode: "read" | "read-write" }
  | { type: "network"; hosts?: string[] }
  | { type: "local-process" }
  | { type: "account"; provider: string; scopes: string[] };

interface InstalledPlugin {
  pluginId: string;
  enabled: boolean;
  installedAt: string;
  configuration: Record<string, string>;
}

interface InstalledSkill {
  name: string;
  description: string;
  path: string;
  scope: "personal" | "project";
}
```

第一阶段不需要立即持久化完整 `PluginManifest`。内置清单可以保留在渲染端，运行配置继续写入 `mcp-servers.json`。

## 10. 技术架构

```text
Renderer 插件中心
        │
        │ IPC：读取、安装、移除
        ▼
Electron Main
        │
        │ 原子读写
        ▼
~/.pi/agent/mcp-servers.json
        │
        │ 新对话启动时读取
        ▼
Coding Agent MCP Extension
        │
        ├─ stdio 子进程
        └─ Streamable HTTP
```

### 10.1 当前 IPC

- `mcp:list`：读取服务器配置。
- `mcp:save`：保存完整服务器映射。
- `mcp:probe`：执行只读连接测试和工具发现。
- `mcp:restore`：恢复配置备份。
- `mcp:reveal`：打开 MCP 配置位置。
- `skill:list`：扫描并返回当前可用技能。
- `skill:reveal`：创建并打开个人技能目录。

### 10.2 目标 IPC

为减少渲染端覆盖整个配置文件的风险，后续改为意图型接口：

- `plugin:listCatalog`
- `plugin:listInstalled`
- `plugin:install(pluginId, configuration)`
- `plugin:remove(pluginId)`
- `plugin:addCustom(definition)`
- `plugin:testConnection(pluginId)`
- `plugin:getStatus(pluginId)`

主进程负责校验、权限判断和原子写入；渲染端只负责呈现。

## 11. 错误处理

### 配置解析失败

显示具体解析错误，保留用户输入，不写入文件。

### 配置文件损坏

阻止保存并提示配置路径。提供“打开文件位置”和“恢复备份”，不能直接返回空列表。

### MCP 启动失败

已安装卡片显示错误状态和精简原因，例如“找不到 npx”或“连接超时”。完整 stderr 放入诊断详情，避免占满主界面。

### 认证失败

显示“重新连接账号”，不要求用户手动编辑 header。

### 名称冲突

内置插件使用稳定 ID。自定义服务器重名时自动生成可见后缀，但在保存前向用户展示最终名称。

## 12. 可访问性与响应式

- 插件中心使用 `main` 页面语义并提供唯一页面标题。
- 所有图标按钮提供 `aria-label`。
- 安装结果和错误使用 `aria-live` 通知。
- 键盘支持按页面顺序使用 Tab 导航。
- 左侧“插件”导航项通过 `aria-current="page"` 表达当前页面。
- 窄窗口从双列降为单列。
- 不只依赖颜色表达安装和错误状态。
- 遵循系统减少动画设置。

## 13. 分阶段实现

### Phase 1：本地插件目录

当前实现范围：

- 大尺寸插件中心。
- 搜索、已安装和推荐插件区域。
- 六个内置插件。
- 一键保存安装和移除。
- 自定义 URL、命令和 JSON。
- 响应式布局。
- 工具名称规范化。
- 可切换的技能主页面。
- 个人与项目技能扫描、搜索和范围筛选。
- 技能空状态与个人技能目录入口。

### Phase 2：可用性与安全

- Agent 连接状态回传。
- 连接测试和错误详情。
- 权限摘要与安装确认。
- 文件系统目录选择器。
- 配置原子写入和损坏恢复。
- MCP `tools/list` 分页。
- 正确的 HTTP SSE 增量解析。
- 自动化测试覆盖。

### Phase 3：账号与远程目录

- 远程签名插件目录。
- 插件详情页。
- OAuth 登录与系统安全存储。
- 版本、更新与禁用。
- 管理员允许列表。

## 14. 验收标准

### Phase 1

- 用户可以在不了解 MCP 的情况下安装任一内置插件。
- 安装和移除操作成功后立即持久化。
- 已安装插件不能重复安装。
- 搜索能按名称、描述和分类过滤。
- 自定义入口默认收起。
- URL、命令和 `mcpServers` JSON 均可解析。
- 文件系统插件未填写目录时不能安装。
- 保存失败不会错误更新 UI 状态。
- 界面在 840px 以下切换为单列。
- 新对话可以加载已安装插件。
- “插件 / 技能”可以在同一主页面内切换，不出现弹窗。
- 技能列表来自 Agent 的真实技能目录，并正确标记个人或项目范围。
- 技能搜索和“全部 / 个人 / 项目”筛选可组合使用。

### Phase 2

- 用户能区分“已安装”和“可用”。
- 连接失败能看到可执行的解决建议。
- 高风险插件在首次启用前展示权限范围。
- 损坏的配置文件不会被空配置覆盖。
- stdio 与 HTTP MCP 均有协议级测试。

## 15. 已知限制与待决策项

1. 内置插件包通过 `npx` 首次运行时可能下载代码，需要明确网络提示与供应链策略。
2. 当前配置修改只对新对话生效；是否支持安全热重载尚未决定。
3. 在线目录由谁维护、如何签名和审核，必须在 Phase 3 开始前确定。
4. OAuth 回调、token 存储和权限撤销需要独立安全设计。

## 16. 设计结论

产品层将外部工具称为“插件”，MCP 作为插件的底层连接方式；将任务说明包称为“技能”。两者在同一个主页面内切换。常用插件通过受控目录安装，自定义 MCP 作为高级入口保留；技能则直接映射 Agent Skills 目录，避免复制出第二套配置来源。第一阶段解决配置复杂度并提供技能管理入口，第二阶段补齐更完整的权限安全，第三阶段再扩展为带账号连接的在线插件平台。

该顺序能在不引入远程服务和 OAuth 基础设施的前提下，先改善大多数用户的安装体验，同时为后续扩展保留清晰边界。
